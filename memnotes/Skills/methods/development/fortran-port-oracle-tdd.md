# Fortran Port With Oracle TDD

Port Fortran numerical code (wannier90, ABINIT, SIESTA) to Python bit-exactly. Test-driven
development (TDD) compares against oracle fixtures generated by the real compiled binary.

## Procedure

1. Pin ground truth from source, not docs. Record file and line for every reader, writer, and
   constant: epsilon values, loop bounds. Fortran list-directed `read(x,*)` needs whitespace
   delimiters. Never rely on field widths alone.
2. Generate oracle fixtures with the real binary. Example: `wannier90.x -pp` writes `.nnkp` and
   exits. Store fixtures in the repo under `tests/fixtures/`. Keep the generator script and log
   in a `.tmp/` scratch directory.
3. Port with explicit order semantics:
   - Selection-sort ties come out reversed against a stable argsort. Use the pattern `argsort(-d,
     stable)[::-1]`.
   - Near-equal comparisons often use epsilon grouping. wannier90 `internal_maxloc` groups within
     eps8 = 1e-8.
   - A sequential scan with hysteresis (replace only when smaller by more than the tolerance) is not
     a global minimum. Port the greedy first-hit chain literally, vectorized per jump.
4. Test exact equality against the oracles, not `allclose`. Add semantic unit tests: unitarity,
   conjugation direction, invariances. Add a dual-oracle independent parser when one exists.
5. Acceptance means the real binary consumes your output. Run it end to end. Assert exit code 0,
   absence of specific error strings (example: "Neighbour not found"), and the expected output
   artifacts (`.chk`).
6. Run review rounds that target fidelity. Expect findings on tie order, absolute-versus-relative
   tolerances, strict band edges, dtype traps (`np.empty_like` on int input), and dead
   validation (`x is None` on pre-allocated arrays).

## Traps seen in practice

- Fortran selection sort places the first-encountered maximum last. The ascending output
  therefore reverses the tie order.
- Shell and neighbor band tests use an absolute tolerance in the scan phase and a relative
  tolerance `d*(1 -/+ tol)` in the acceptance phase.
- Square-array tests mask row and column layout bugs. Always add one rectangular test.
- Port validation-only Fortran loops (symmetry checks) too. They give cheap hard errors.
