# Story 001: Complete and save deterministic migration plans

## User Story

As a Project maintainer, I want a complete reviewable migration plan generated by an offline command, so that owners, file moves and link rewrites need no agent-driven editing.

## Scope

Extend `kosmic_specs.migration_plan` and its existing CLI entry point. Implement Architecture AD-M01/AD-M02 and the planning parts of AD-M03/AD-M04. No apply or authoritative migration occurs in this Story.

## Acceptance Criteria

- [ ] AC1: The actual `migrate-subprojects-plan` CLI preserves stdout mode and supports exclusive `--output PATH`; saving never overwrites an existing file or changes source records.
- [ ] AC2: A fixed snapshot and assignments produce an identical versioned plan and digest containing all recomputation inputs, complete legacy inventory, existing owners, ProjectEntry and live-reference hashes, target preconditions, candidate hashes and intended write scope.
- [ ] AC3: Declared ancestry determines owners. Explicit assignments resolve ambiguous ownership; cycles, dangling/conflicting parents and destination collisions remain explicit blockers rather than inferred prose decisions.
- [ ] AC4: Rewrites cover ancestry/dependency metadata and supported live Markdown links, reference links and images outside code fences, including active inbound references and Project/owner indexes. Links resolve to the intended final identities; unsupported live forms are reported as blockers.
- [ ] AC5: Existing canonical shared local IDs and lifecycle decisions are retained. Legacy shared identity metadata is deterministic; unrelated content, historical evidence and logs remain byte-identical.
- [ ] AC6: Plans include proposal fingerprint disposition and bound/unbound STATUS inputs without installing adapters, creating bindings, approving records or manufacturing completion authority.
- [ ] AC7: Focused behavior regressions and an actual CLI smoke prove the preceding criteria; saved plan schema and command documentation are updated and reviewed.
