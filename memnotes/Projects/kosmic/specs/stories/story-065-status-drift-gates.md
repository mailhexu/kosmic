# Story 065: Status Drift Gates

## User Story

As a vault maintainer,
I want STATUS.md drift to fail loudly,
So that no agent works from a stale or hand-edited status picture.

## Acceptance Criteria

- [ ] `validate --project` fails with `STATUS_STALE` when a bound STATUS.md differs from generated bytes; passes after regeneration; warns (never fails) when the project has no bound root.
- [ ] `check-completion` fails before its early returns when the work item's project has a bound root whose STATUS.md is stale, naming the regeneration command.
- [ ] Drift detection runs even when the only change is spec frontmatter (no file-count change).
- [ ] Fixture tests cover: fresh drift, regenerated match, unbound warning, completion blocked by stale status and unblocked by regeneration.
