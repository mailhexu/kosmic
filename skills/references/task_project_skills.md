# Shared Skill Library and Project Projection Migration

Use this contract to validate Project knowledge, migrate legacy Project Skill Pairs, generate or resolve the vault-level Shared Skill Library, and install its single native router.

## Invariants

- `notes/` is authoritative Project Knowledge and a dual-native Obsidian/OKF v0.2 bundle; generated skill packages are disposable projections.
- The bundle-root `notes/index.md` declares only `okf_version: "0.2"` and groups concepts for progressive disclosure.
- Every other note starts with YAML on line 1, has a non-empty `type`, and uses relative standard Markdown links.
- Each Project has an immutable `project_id` and exactly `{PROJECT_ID}-usage` plus `{PROJECT_ID}-development`.
- Usage projects stable `audience: usage` and `audience: both` notes.
- Development projects stable `audience: development` notes and requires Usage for consumer and shared behavior.
- A stable note without `audience` is Unscoped Knowledge and remains Development-only until reviewed.
- Specs and logs never project directly. Distill durable behavior into stable notes first.
- Both skills describe the same `working_state` from `ProjectEntry.md`.
- The generated `skills/` tree is also OKF v0.2 conformant. Publication and installation are atomic; never edit canonical or installed projections.
- Every Project has a vault-only `mathdocs/` directory with the reserved `index.md`; paired derivations never project into Usage or Development skills.

## Projection-Eligible Note Metadata

```yaml
type: Project Knowledge
status: stable
audience: development | usage | both
usage_stale: false
# stale_after: 'YYYY-MM-DD'  # optional real effective date
```

`usage_stale: true`, `draft`, `deprecated`, a reached `stale_after`, or material outside `notes/` excludes the document. The Projection CLI copies eligible note bodies under fresh OKF frontmatter and records source path and SHA-256 provenance in each topic reference.
Stable regular notes may declare `derivations: [mathdocs/{slug}.py]`; their authoritative display equations must match checked MathDoc result markers. Use Task M and `check-math` rather than hand-editing generated results.

## Shared Library Commands

Resolve `{KOSMIC_SKILL_DIR}` to the installed Kosmic Orchestrator skill and `{VAULT}` to the vault containing sibling `Projects/` and `Skills/`.

```bash
# Rebuild disposable catalog, manifest, domain indexes, and root router.
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py generate-library \
  --vault "{VAULT}"

# Validate authoritative domain/topic documents and exact generated bytes.
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py validate-library \
  --vault "{VAULT}"

# Produce a canonical hash-pinned plan. Use --route instead of --query when known.
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py resolve-library \
  --vault "{VAULT}" --project "{PROJECT_ID}" --role usage|development|auto \
  --query "{TASK}" --max-bytes 32768 --max-domains 4 --max-topics 8

# Recheck every plan/source hash and emit the ordered Recipe Packet.
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py load-library \
  --vault "{VAULT}" --plan "{PLAN_JSON}"

# Migrate only an explicitly complete old-reference → new-topic map.
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py migrate-library \
  --vault "{VAULT}" --project "{VAULT}/Projects/{TARGET}" \
  --assignments "{ASSIGNMENTS_JSON}"
```

Resolution is all-or-none. Ambiguity, stale hashes, unknown/cyclic dependencies, invalid audience edges, or byte/domain/topic overflow emits no Recipe body. `load-library` never re-ranks. Domain `SKILL.md` files load dynamically through the plan; detailed Usage/Development topics remain ordinary Markdown.

## Legacy Project Projection Commands

Generate or refresh a legacy canonical pair for migration input:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py generate \
  --project "{VAULT}/Projects/{TARGET}"
```

Validate the authoritative OKF notes bundle, projection provenance, and drift:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py validate \
  --project "{VAULT}/Projects/{TARGET}"
```

Validate one Skill Proposal and print its canonical fingerprint:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py validate-proposal \
  --project "{VAULT}/Projects/{TARGET}" \
  --proposal "{VAULT}/Projects/{TARGET}/specs/skill-proposals/{DATE}-{SLUG}.md"
```

Review Unscoped Knowledge and projection drift:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py review \
  --project "{VAULT}/Projects/{TARGET}"
```

Migrate an existing Project:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py migrate \
  --project "{VAULT}/Projects/{TARGET}" \
  --project-id "{PROJECT_ID}"
```

Migration is restartable and transactional for `notes/`. It moves frontmatter to line 1, adds `type`, maps legacy `validated` to `stable`, conservatively maps undated legacy `stale` to `draft`, renames `TOC.md` to `index.md`, and converts unambiguous Wikilinks to relative Markdown links. Ambiguous links, embeds, and block references stop migration without partial note edits. Publication remains blocked until real stable Usage knowledge exists.

Execute and compare active Math Derivations without changing files:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py check-math \
  --project "{VAULT}/Projects/{TARGET}" [--slug "{SLUG}"] [--timeout 30]
```

After reviewing a derivation change, add `--update --source-root "{SOURCE_ROOT}"` to refresh all selected paired-note metadata and generated result regions atomically.

Check a story or quick task before completion:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py check-completion \
  --project "{VAULT}/Projects/{TARGET}" \
  --work-item "{WORK_ITEM}" \
  --source-root "{SOURCE_ROOT}"
```

Work items must declare `consumer_interface_change: true | false`. New templates also declare `proposal_required: false`; set it true and add exactly one `skill_proposal` path when Task P is required. The proposal must validate and have a non-pending decision before completion. When Consumer Interface change is true, `related_notes` must name current stable `usage` or `both` notes, and the canonical pair must pass drift validation. Work items may additionally declare `evidence_packs: [{slugs}]`; every declared pack must exist under `evidence/` and have at least one draft-or-stable note linking it via `evidence:` frontmatter, or the gate fails naming the slug.

Math-derived work items declare both `derivations: [{slug}, ...]` and `math_implementation_files: [relative/path, ...]`. Each listed file must remain under `--source-root` and contain a matching `MathDoc: {project_id}/{slug}[#result-name]` identifier.

`validate` additionally checks the Experience layer: every Evidence Pack's `MANIFEST.md` (kind `execution|research`, `produced_by`, ISO `date`, non-empty `summary`, and a body file-role list matching the pack contents exactly) and the `impact.md` ledger's fixed six-field entries. Evidence packs and the ledger live outside `notes/` and never project into the Skill Pair; `generate` appends publication entries to the ledger after each atomic publication.

MANIFEST frontmatter may optionally carry code provenance: `git_head` (commit
hash) and `worktree_tree` (tree hash or `clean`). Present ⇒ both required and
shape-checked (40/64 lowercase hex). Use the `provenance` command
(`--repo PATH`, default cwd) to print paste-ready lines computed via a
temporary index — no working-tree or index side effects.

Projected reference bodies are package-consistent: a Markdown link whose target is not projected into the same Skill Pair package (draft target, other-audience target) is demoted to bold plain text, and `generate` warns on stderr naming each demoted link. Links inside code fences, external URLs, and non-Markdown targets are untouched.

## Install Adapters

Install one native Shared Skill Router and remove managed per-Project Usage/Development packages only after byte and identity verification:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py install-library \
  --vault "{VAULT}" \
  --adapter opencode|claude-code|codex|omp \
  --home "{HOME}"
```

Verify the installed router and absence of managed legacy pairs:

```bash
python3 {KOSMIC_SKILL_DIR}/scripts/kosmic_project_skills.py check-library-installation \
  --vault "{VAULT}" \
  --adapter opencode|claude-code|codex|omp \
  --home "{HOME}"
```

Installation reports only on-disk success. Reload or start a new adapter session and inspect its skill inventory before claiming activation. The inventory must contain `memnotes-skills`; ABINIT, TB2J, Kosmic, and other Domain Skills are dynamically loaded vault documents and must not appear as separate native skills. A collision with an unmanaged `memnotes-skills` path or any failed copy/removal/verification preserves the prior complete inventory.
